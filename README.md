# Gharkaam

A small PWA for one family to share recurring chores and keep the home stocked.

- **No accounts.** One family passcode per device, then a Netflix-style profile picker.
- **Instant updates** between phones via Supabase Realtime (data-less "something changed" pings).
- **Daily digest** push notification around 8 AM IST.

> Status: phase 1 of 6 (setup, passcode gate, profiles). Chores, inventory, PWA and push follow.

## Stack

Next.js 16 (App Router, server actions) · TypeScript · Supabase Postgres + Realtime · Drizzle ORM · shadcn/ui (Base UI) + Tailwind v4 · Vitest · Vercel (Hobby). Timezone is fixed to Asia/Kolkata.

## Project layout

```
src/
  proxy.ts            passcode gate (Next.js 16's renamed middleware)
  app/                routes: pages read via lib/services, write via actions/
  actions/            thin 'use server' functions: validate (zod) → service → revalidate
  components/         display only; may import actions and pure domain helpers
  lib/
    domain/           pure business logic (recurrence, rotation, due dates) + Vitest tests
    services/         orchestration: session, permissions, transactions; returns DTOs
    db/               Drizzle schema, client, and SQL-only query functions
    validation/       zod schemas shared by forms and actions
drizzle/              SQL migrations (generated by drizzle-kit)
scripts/seed.ts       sample data
```

ESLint enforces the layering (see `eslint.config.mjs`), so the UI can be replaced without touching logic.

## Local setup

Requirements: Node 22+, npm.

1. `npm install`
2. Create a Supabase project (free plan) at https://supabase.com/dashboard.
3. `cp .env.example .env.local` and fill it in:
   - **DATABASE_URL**: Supabase → **Connect** → *Transaction pooler* string (port **6543**). Replace `[YOUR-PASSWORD]`.
   - **DIRECT_DATABASE_URL**: same dialog → *Session pooler* string (port **5432** on the `pooler.supabase.com` host).
     Don't use the "Direct connection" string: on the free plan it is IPv6-only and Vercel can't reach it.
   - **FAMILY_PASSCODE**: the passcode your family will type once per device.
   - **SESSION_SECRET**: `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`
   - The Realtime, VAPID and cron values are needed from later phases; leave them for now.
4. Check the connection: `npm run db:check` (explains what is wrong if it fails), then create the tables: `npm run db:migrate`
5. Start the app: `npm run dev` → http://localhost:3000

The first visit asks for the passcode, then lets you create the first profile, which is admin.
Add everyone else under **Settings → Manage profiles**.

## How access works

- `FAMILY_PASSCODE` unlocks a device and sets a signed, httpOnly cookie that lasts 400 days (the browser maximum).
- Changing `FAMILY_PASSCODE` (or `SESSION_SECRET`) in Vercel signs every device out.
- On iPhone, the Home Screen app keeps separate storage from Safari, so enter the passcode once more inside it.
- "Admin" is an honour-system flag: it hides the profile management screens but isn't a security boundary.
- Every table has row level security enabled with no policies, so Supabase's public API can't read anything.
  The app connects directly through Drizzle and isn't affected.

## Deploying to Vercel

1. Push this repo to GitHub.
2. In Vercel: **Add New → Project**, import the repo (framework: Next.js, defaults are fine).
3. Add the environment variables from `.env.local` under **Settings → Environment Variables**.
4. Deploy. Run `npm run db:migrate` locally whenever a new migration is added (it targets the same Supabase database).
